# Android 작은 화면 졸음 측정

2026-09-10: 사용자가 홈 화면·다른 앱 위의 작은 화면에서 졸음 측정 유지 요청.

| 단계 | 구현 범위 | 확인 기준 |
|---|---|---|
| Android | PiP 지원 Activity, 자동 전환, 명시적 전환, 종료 액션, 생명주기 | 측정 중만 진입, 닫기/화면 꺼짐은 카메라 종료 |
| 앱 | 네이티브 상태 연결, 작은 카메라 화면, 회전·가시성 구분 | PiP 크기 변경은 측정 재시작 없이 처리 |
| 검증 | 회귀, APK, 가능한 에뮬레이터 및 단말 | 빌드와 실제 동작 증거 구분 |

- Android 8(API 26) 이상이며 PiP 지원 기기에서 사용. Android 12 이상 자동 진입 API, 8~11에서는 홈 이동 콜백 사용.
- 기본 옵션 켜짐. 카메라 준비가 끝나 실제 측정 중일 때만 자동 전환 활성화. 옵션은 측정 종료 후 변경 가능.
- PiP는 카메라·눈 표시·실제 측정 상태를 중심으로 표시. 경고 시 기존 보유/랜덤 영상 재생 방식을 유지.
- 완전히 숨겨진 백그라운드 촬영 기능은 추가하지 않음. 작은 창 종료, 잠금/화면 끄기, 미지원·진입 거부 후 앱 숨김은 카메라 종료.
- Android onStop에서 카메라 트랙 해제와 JS 세션 중지. 감지/경고 영상 갱신이 멈추면 네이티브 8초 감시 타이머가 종료 처리.
- PiP 전환·복귀의 크기 변경과 실제 기기 회전을 구분. 카메라를 기다리는 동안 홈으로 나가도 늦게 완료된 초기화가 측정을 다시 켜지 않도록 세대 번호로 취소.
- 별도 오버레이 권한·백그라운드 위치·포그라운드 서비스 권한을 추가하지 않음. 웹 미리보기에서는 PiP 비활성 안내, 기존 숨김 시 종료 유지.

참고: [Android PiP 및 카메라 공식 안내](https://developer.android.com/develop/ui/views/picture-in-picture), 로컬 Capacitor 8.4.2 BridgeActivity/Bridge/Cordova 생명주기 소스.

## 검증 결과와 남은 확인

- TypeScript, 졸방 웹 빌드, Android assembleDebug 성공. 회귀 17개 파일/122개 테스트 통과.
- 앱 전용 Android 통합 테스트 APK `:app:assembleDebugAndroidTest` 빌드 성공. 테스트는 실제 WebView 카메라·분석 시작 → 홈 자동 PiP → 16초 프레임 진행 및 heartbeat → 전체 화면 복귀 → 수동 PiP → 종료 액션을 검증하도록 작성.
- 테스트 **실행은 미완료**. 연결된 실제 단말 없음. 이 PC의 에뮬레이터가 부팅 중 Windows 종료 코드 -1073741819(0xC0000005)로 종료. 두 SDK 경로, 소프트웨어/호스트 그래픽, 하드웨어 가속 해제 설정에서도 부팅하지 못함.
- 처음 모든 모듈 테스트 APK를 빌드하는 명령은 기존 Cordova 라이브러리의 Kotlin 중복 클래스에서 실패. 대상 앱만 빌드하는 `:app:assembleDebugAndroidTest`는 통과했으며 앱 배포 빌드에는 영향 없음.
- 따라서 실제 PiP 진입, 실제 카메라/분석 연속성, 창 닫기·화면 끄기 시 카메라 해제, 티맵 음성과 졸음 경고음의 동시 사용은 아직 확인되지 않음.
- 배포 파일은 개발용 서명의 졸방 0.1.1(versionCode 2). 웹 미리보기는 네이티브 PiP 검증 수단이 아님.

## 휴대폰 확인 순서

1. 최신 졸방 APK를 업데이트 설치. Android의 졸방 ‘화면 속 화면’ 사용 허용 상태 확인.
2. 설정에서 ‘작은 화면으로 측정 유지’를 켜고 앱 화면에서 카메라 허용·기준 측정 완료.
3. 홈으로 이동하거나 ‘작은 화면으로 보기’를 선택. 작은 창에서 영상과 감지 상태가 갱신되는지 확인.
4. 티맵을 열어 작은 창이 유지되는지 확인. 정차 상태에서만 경고 영상·음성과 전체 화면 복귀를 확인.
5. 작은 창 종료 액션/창 닫기/화면 끄기 각각 카메라 사용 표시가 해제되는지 확인. 자동 전환 끔·PiP 권한 거부·다른 앱의 카메라 점유도 확인.

자동 통합 검증 명령(개발 환경): 연결할 Android 28 이상 테스트 기기를 지정한 뒤 `gradlew.bat :app:connectedDebugAndroidTest` 실행. 테스트가 앱의 카메라 권한을 부여하고 홈 화면 이동을 수행하므로 테스트용 단말에서 실행.
