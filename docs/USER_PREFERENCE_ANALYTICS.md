# Wake Drive 사용자 이용 선호 분석

전체 이벤트와 운영 방법은 [Firebase 개발 인수인계](FIREBASE_HANDOFF.md)를 참고한다. 이 문서는 이용 선호 확장의 상세 구현·검증 기록이다.

2026-09-10 · Android 0.1.9 / versionCode 10

## 이번에 추가한 항목

‘성향’은 앱에서 관찰한 선택과 이용 습관을 뜻한다. 성격, 건강, 졸음 질환, 위험 운전자 등 개인 특성을 추정하거나 등급을 매기지 않는다. 앱이 임의로 경고 영상을 추천·변경하는 기능도 추가하지 않았다.

| 알고 싶은 내용 | 추가 기록 | 활용 방법 |
|---|---|---|
| 어떤 영상을 계속 선택하는가 | 사용자 속성 `applied_video`, 기존 영상 선택·적용 이벤트 | 현재 적용 영상별 사용자 비교. 설정 변경은 실제 선호의 단서로만 해석 |
| 고정 또는 랜덤 재생을 선호하는가 | `playback_mode`: APPLIED / RANDOM_OWNED | 재생 방식별 재방문·측정 이용 비교 |
| 소리와 작은 화면을 어떻게 쓰는가 | `sound_mode`: on/off, `pip_mode`: on/off/unsupported | 조작 성향과 기능 사용 비교. 작은 화면 속성은 설정 여부이며 실제 PiP 체류 시간이 아님 |
| 영상 수집을 얼마나 하는가 | `library_size_band`: one / two_to_five / six_plus | 보유량별 광고 해제·재방문 비교 |
| 설정을 무엇으로 바꾸는가 | `preferences_snapshot`, `setting_change` | 첫 동의/앱 진입에는 현재 값 1회. 실제 변경만 setting_name/setting_value로 전송 |
| 어떤 영상을 보고 선택하는가 | `video_impression`, `library_filter` | 50% 이상 보이는 영상만 노출 기록. 영상·필터·보유 여부별 노출 사용자와 선택 사용자 비교 |
| 미리보기를 얼마나 보는가 | `video_watch_progress`, `video_play_exit`, 완료/오류 이벤트의 watched_seconds/watch_percent | 25·50·75% 시청, 중도 종료, 끝까지 도달한 경우를 구분 |
| 시작 단계에서 왜 이용을 못 하는가 | `detection_start_result` | 성공/실패, 준비 시간, permission / camera_setup / analysis_setup 단계 비교 |

기존 신규·재방문/세션 통계, 클릭, 보상 요청→보상 결과→다운로드 및 잠금 해제, 측정 시간·GPS 집계와 함께 사용한다. 개인 이름, 이메일 또는 별도 로그인 ID를 추가하지 않는다. Firebase 앱 인스턴스 식별은 동의한 기기의 통계를 연결하므로 이 데이터를 완전 익명이라고 표현하지 않는다.

## 집계 기준과 한계

- 사용자 속성 5개는 현재 앱 설정의 스냅샷이다. 미동의 기간의 변경 기록을 저장하거나 동의 후 재전송하지 않는다. 앱 재진입 시 현재 값은 다시 갱신한다.
- 속성 값은 TypeScript와 Android 양쪽에서 허용 목록으로 검증한다. 이메일·자유 텍스트·임의 영상 ID를 사용자 속성으로 넣을 수 없다.
- 설정 변경에는 사용자의 직접 변경뿐 아니라 영상 적용으로 고정 재생이 선택되는 등 앱의 정상 처리에 따른 변경도 포함한다. 클릭 이벤트와 조합해 해석한다.
- 영상 노출은 홈 진입 1회당 영상 ID·필터별 최대 1회이다. 선택 영역과 목록 중복을 제거하며 미리보기 창 뒤와 백그라운드 노출은 집계하지 않는다. 노출 수 자체를 광고 노출 또는 시청 수로 해석하지 않는다.
- 선택 버튼을 반복 누를 수 있으므로 이벤트 횟수 나눗셈을 고유 사용자 선택률이라고 부르지 않는다. 같은 영상의 노출→선택 **사용자 퍼널**로 확인한다.
- 시청 시간은 진행하는 미디어 시간과 시간 간격 중 작은 값을 보수적으로 누적한다. 탐색 점프, 정지, 버퍼링, 2초 넘는 업데이트 공백은 제외한다. 실제 주의 집중 여부를 판단하지 않는다.
- 영상의 끝으로 탐색해도 ended는 발생할 수 있다. `video_play_complete`와 시청 비율을 함께 봐야 한다. 시청 비율은 재생 속도·중복 구간의 영향을 받는 근사치이며 고유 프레임 시청 비율은 아니다.
- 완료·오류·중도 종료의 시청 시간은 **종료 이벤트들만** 합산한다. 25/50/75 진행 이벤트에는 시간 합계를 반복 전송하지 않는다.
- 앱 강제 종료는 중도 종료 콜백이 보장되지 않는다. 영상 재생 시작 대비 종료 이벤트의 차이를 모두 사용자 이탈로 단정하지 않는다.
- 감지 시작 결과는 실제 카메라 준비 시도 이후 성공/오류를 기록한다. 안전 안내에서 취소, 준비 중 앱 종료 및 미지원 웹 환경은 실패 이벤트에 포함하지 않는다.
- GA4 수치 측정항목은 합계로 보일 수 있다. 평균 시청 비율·평균 준비 시간은 해당 이벤트 횟수로 나눈다. 신규 맞춤 정의가 일반 보고서에 나타나는 데 시간이 걸릴 수 있다.

## Firebase에서 보는 위치

[맞춤 정의](https://analytics.google.com/analytics/web/?authuser=0&hl=ko#/p553479695/customdefinitions/hub) / [DebugView](https://analytics.google.com/analytics/web/?authuser=0&hl=ko#/p553479695/realtime/debugview)

등록한 추가 정의:

- 사용자 범위 5개: applied_video, playback_mode, sound_mode, pip_mode, library_size_band.
- 이벤트 범위 6개: setting_name, setting_value, filter, ownership, milestone, failure_stage.
- 측정항목 3개: watched_seconds(초), watch_percent(일반), startup_seconds(초).

이전 정의를 합치면 측정기준 16개(이벤트 11·사용자 5), 측정항목 12개, 평균 시속 계산 지표 1개다. 사용자 속성은 GA4 비교 및 탐색의 분류 기준으로 사용할 수 있다. [공식 사용자 속성 안내](https://firebase.google.com/docs/analytics/android/user-properties)

분석할 표/퍼널:

1. 영상별: 노출 사용자 → 선택 사용자 → 광고 보상 → 잠금 해제 → 적용. 영상 ID로 구분.
2. 시청 품질: preview와 warning을 분리해 재생 시작 → 25 → 50 → 75 → 완료, 중도 종료 시간 비교.
3. 기능 선호: 고정/랜덤, 소리 on/off, 보유 영상 수 구간별 신규/재방문 사용자 및 측정 세션 비교.
4. 시작 마찰: detection_start_result의 성공/실패·failure_stage별 횟수와 평균 startup_seconds.

## 동의 및 기존 흐름

통계 기본 OFF, 설정에서 선택 동의·철회. 안내 문구에 추가 수집 항목을 반영했다. 철회 시 사용자 속성을 지우고 SDK의 기기 내 Analytics 데이터를 초기화한다. 이미 전송된 서버 데이터 삭제는 별도 절차다. 통계를 꺼도 카메라 감지·광고 보상·잠금 해제·영상 적용 흐름은 동일하다.

- 자동 테스트 21개 파일 140개 통과. 설정 최초값/변경 중복 방지, 미동의·철회 및 사용자 속성 전송 차단, 허용 목록, 미디어 탐색·정지·버퍼링 시간 제외, 중도 종료/완료 구분 검증.
- TypeScript 검사 및 0.1.9 Android 빌드 통과. 실제 휴대폰 업데이트 설치 성공, versionCode 10 / versionName 0.1.9 확인. 웹·APK 파일 일치 검사 통과.
- Firebase 추가 정의 14개 등록 확인.
- 실기 UI 테스트는 잠금 해제 및 통계 동의 상태에서 소리 설정 변경→보유 필터→실제 video-0 재생→중도 종료를 수행한다. 소리 설정을 원래대로 복구하고 광고 보상·소유권은 변경하지 않는다.
- 실기 Android `nativePreferenceAllowlist` 테스트 OK (1 test). 허용 영상/재생 방식 수락, 임의 개인 문구/이메일/영상 ID 거절 확인.
- **실제 서버 수신 확인**: 12:14경 실제 앱 초기화로 `preferences_snapshot` 수신. `applied_video=video-0`, `library_size_band=two_to_five`, `pip_mode=on`, `playback_mode=APPLIED`, `sound_mode=on` 매개변수 및 사용자 속성 확인. 합성 속성 값을 넣은 검증이 아니다.
- 실제 미리보기 재생·중도 종료 및 설정 변경 조작 테스트는 휴대폰 잠금으로 실행하지 못했다. 해당 테스트 코드는 준비됐으며 자동 테스트와 설정 스냅샷 서버 수신 성공을 이 UI 검증 성공으로 대신하지 않는다.
- 테스트용 APK 삭제 및 Firebase 디버그 모드 해제 후 앱 재실행. 기존 이용 통계 동의·소리·영상 보유 상태는 유지.
