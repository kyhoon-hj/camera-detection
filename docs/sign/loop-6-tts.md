# SIGN LOOP 6 — 한국어 TTS

## 구현 결과

SIGN LOOP 5에서 생성·확정한 한국어 문장을 기기의 한국어 TTS 엔진으로 읽는 흐름을 추가했다. 서버는 재생할 문장과 음성 선호·속도·자동 재생 정책을 검증하고, 실제 음성 합성은 브라우저 또는 운영체제의 기기 내 엔진이 담당한다.

음성 파일을 서버에 생성하거나 저장하지 않으며 외부 TTS 서비스로 문장을 보내지 않는다.

## 지원 설정

| 설정 | 값 |
|---|---|
| 언어 | `ko-KR` |
| 음성 | `SYSTEM_KOREAN`, `FEMALE_PREFERRED`, `MALE_PREFERRED` |
| 속도 | 0.5×~2.0× |
| 자동 재생 | 기본 `false` |
| 자동 재생 전 확인 | 기본 `true` |

음성 성별은 운영체제 음성 이름을 바탕으로 우선 선택하는 선호값이다. 해당 음성이 없으면 설치된 첫 번째 한국어 음성으로 안전하게 대체한다.

## 재생 정책

- `MANUAL`: 사용자가 `음성으로 전달`을 눌러 현재 확정문 또는 선택 후보를 재생한다.
- `AUTO`: 세션 설정에서 자동 재생이 켜져 있어야 한다.
- `confirmBeforePlayback=true`인 자동 재생은 번역 상태가 `CONFIRMED` 또는 `CORRECTED`일 때만 허용한다.
- `다시 듣기`는 가장 최근 재생 문장과 동일한 설정으로 새 재생 요청을 만든다.
- 새 음성을 재생할 때 진행 중인 브라우저 음성을 취소해 문장이 겹치지 않게 한다.

긴급 표현이라도 SIGN LOOP 6에서는 확인 정책을 임의로 우회하지 않는다. 긴급 알림·재현율 정책은 전문가 검증과 함께 별도 단계에서 확장한다.

## API

- `GET /v1/sign/tts/capabilities`: 엔진, 언어, 음성 선호, 속도 범위와 오프라인 가능 여부.
- `GET /v1/sign/tts/{sessionId}/settings`: 현재 세션 설정.
- `PUT /v1/sign/tts/{sessionId}/settings`: 음성·속도·자동 재생 정책 변경.
- `POST /v1/sign/tts/{sessionId}/play`: `AUTO` 또는 `MANUAL` 재생 계획 생성.
- `POST /v1/sign/tts/{sessionId}/replay`: 가장 최근 문장 다시 듣기.

재생 응답 예시:

```json
{
  "utteranceId": "ksltts_uuid",
  "text": "병원이 어디에 있는지 알려주세요.",
  "language": "ko-KR",
  "voicePreference": "FEMALE_PREFERRED",
  "rate": 0.9,
  "mode": "MANUAL",
  "replay": false,
  "engine": "DEVICE_TTS",
  "networkRequired": false
}
```

## 개발 콘솔

콘솔의 `수어 통역` 모드에 다음 UI를 추가했다.

- 인식된 Gloss와 한국어 후보·신뢰도 표시
- 후보 문장 사용자 확정
- 시스템 기본·여성 우선·남성 우선 선택
- 0.5×~2.0× 속도 조절
- 확정 후 자동 재생과 자동 재생 전 확인 설정
- `음성으로 전달`, `다시 듣기`

브라우저 보안 정책상 첫 음성 재생에는 사용자의 버튼 조작이 필요할 수 있다. 한국어 음성이 설치되지 않은 환경에서는 운영체제 TTS 설정에서 한국어 음성 데이터를 설치해야 한다.

## 개인정보와 생명주기

TTS 설정과 최근 재생 문장은 세션 메모리에만 둔다. Gloss 시퀀스 삭제, 카메라 중지 또는 모드 변경 시 번역 상태와 함께 삭제한다. 음성 파일·재생 오디오는 저장하지 않는다.
