# SIGN LOOP 10 — 전문가 검수와 승인 데이터셋

## 구현 결과 (2026-07-20)

명시적으로 활용 동의를 받은 사용자 교정본을 전문가가 승인·반려하고, 다중 역할 승인이 끝난 항목만 학습 후보로 내보내는 로컬 검수 흐름을 구현했다.

## 검수 대상과 범위

- 현재 검수 단위는 `TEXT_GLOSS_CORRECTION`이다. 원문, 교정 한국어, Gloss 시퀀스, 교정 사유, 도메인을 포함한다.
- 원본 영상과 랜드마크는 저장하지 않는다.
- 따라서 의미 보존, 한국어 자연스러움, 오인식 위험은 평가할 수 있지만 수어 동작의 자연스러움, 비수지 표현, 지역·연령 변이는 이 데이터만으로 평가할 수 없다.
- 평가 불가능한 항목은 각 레코드의 `unavailableCriteria`에 명시한다. 이 항목들은 추후 별도 동의를 받은 영상 데이터 검수에서 다뤄야 한다.

## 역할과 승인 정책

검수 역할은 농인 수어 사용자, 한국수어 통역사, 한국수어 교육자, 분야 전문가, 접근성 UX 전문가다.

- 일반·공공·주차·교통: 서로 다른 역할 2개의 승인이 필요하며, 그중 하나는 농인 수어 사용자 또는 한국수어 통역사여야 한다.
- 의료·금융·재난: 농인 수어 사용자 또는 한국수어 통역사와 해당 분야 전문가의 승인이 모두 필요하다.
- 한 검수자는 같은 항목을 두 번 검수할 수 없다. 식별명은 저장 전에 해시한다.
- 승인 점수 기준은 의미 보존 4점 이상, 한국어 자연스러움 4점 이상, 오인식 위험 2점 이하다.
- 반려에는 의견이 필수이며 즉시 최종 `REJECTED` 상태가 된다.

상태는 `PENDING_REVIEW → IN_REVIEW → APPROVED` 또는 `REJECTED`로 전이한다. 최종 상태의 항목은 다시 검수할 수 없다.

## 학습 후보 격리

`APPROVED`이며 `trainingEligible=true`인 항목만 `/v1/admin/sign/training-candidates`에 노출한다. 내보내기 데이터에는 세션 해시와 동의 참조를 포함하지 않는다. 승인 전·검수 중·반려 항목은 학습 및 정식 사전 후보에서 제외된다.

## 로컬 관리자 API

- `GET /v1/admin/sign/reviews`
- `GET /v1/admin/sign/reviews/summary`
- `GET /v1/admin/sign/reviews/{feedbackId}/history`
- `POST /v1/admin/sign/reviews/{feedbackId}`
- `GET /v1/admin/sign/training-candidates`

개발 콘솔의 `EXPERT REVIEW` 패널에서 역할, 점수, 의견, 승인·반려, 이력을 확인할 수 있다. 현재 서버는 루프 개발용 로컬 바인딩을 전제로 하며 응답에 `LOCAL_ADMIN_ONLY`를 표시한다. 외부 배포 전에 실제 관리자 인증·RBAC·감사 보존 정책을 추가해야 한다.

## 검증 기준

- 일반 데이터가 한 역할의 승인만으로 학습 후보가 되지 않는다.
- 고위험 도메인은 수어 검수자와 분야 전문가 조합만 승인된다.
- 점수 임계값, 중복 검수자, 최종 상태 재검수를 차단한다.
- 반려 데이터는 학습 후보 내보내기에 포함되지 않는다.
- 검수 이력과 요약 통계가 재시작 가능한 영속 큐에 함께 저장된다.
